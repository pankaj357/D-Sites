# evaluation/results — held-out evaluation outputs

Every file is regenerated by a script in `evaluation/scripts/` (run with
`/tmp/dsites_venv/bin/python`; FIMO 5.5.4 at `/Users/admin/meme/bin/fimo`;
global seed 42). Protocol details are in each script's header (Methods-ready).
**Current model: dsites v1.3.0 — shape features from the published DNAshape
pentamer query table (Zhou et al. 2013, NAR 41:W56-W62, via DNAshapeR
v1.38.0's QueryTable; verified bit-identical to DNAshapeR getShape, see
`pqt_python_vs_R_verification.json`). See `CHANGELOG.md`.***

## Headline numbers (5-fold grouped CV, n_estimators=300, seed 42)
- recall = recovered test sites / all test sites; recall_in_space = same over
  sites falling inside the promoter search space (see cv_summary.csv).
- **IN-SPACE (single harmonized definition, fixed after Phase 3): a site is
  in-space iff its interval +/-10 bp pad intersects ANY promoter window of
  the scan universe** (independent of per-fold train-site exclusions).
  Counts: AmrZ 161/363, GlxR 159/201, CodY 224/260, FNR 89/97 -- identical
  in cv_{TF}.json, fimo_fair_{TF}.json and cv_summary.csv. Per-fold JSONs
  also carry n_test_sites_scorable (in-space sites with >=1 scored window in
  that fold) for transparency. Updated recall_in_space means: AmrZ 0.752,
  GlxR 0.772, CodY 0.965, FNR 0.910.
- FIMO rows are ONE GLOBAL run on the identical search space (not per fold).

## Important result notes
1. **Search-space coverage bounds recall**: only 161/363 AmrZ, 159/201 GlxR,
   224/260 CodY, 89/97 FNR sites fall inside -300/+50 promoter windows; the
   rest (many intragenic ChIP sites) are unrecoverable by construction and are
   reported separately (n_sites_in_space, recall_in_space).
2. **Window-level precision is small for ALL methods** (prevalence ~3e-3):
   ~20-26 windows overlap each padded site but only 1-2 are true motif
   matches. Window-level PR curves therefore hug the x-axis; the informative
   views are site-level recall, recall@top5%, the matched-count comparisons
   in `fimo_fair_{TF}.json`, and `pr_sitelevel_{TF}.png`.
3. **Matched-count**: at FIMO's default N (p<1e-4) both methods are
   precision-limited; at D-Sites' top-5% N, recall_in_space is comparable
   between methods. Verified that D-Sites pooled probabilities are NOT
   tie-degenerate at the top (<=0.26% of windows have prob>=0.9).
4. FIMO command (recorded in each json): `fimo --thresh 1e-2 --text --oc OUT
   --bfile GENOME.bg MOTIF.meme promoters.fasta` — positions with p>=1e-2 are
   treated as score 0; `--bfile` gives FIMO the same genome background that
   D-Sites' PWM uses (documented deviation from the spec's literal command).
5. **Phase 4 (operon-level FNR enrichment, v1.3.0 model)**: NO prediction
   set shows significant enrichment for DEP operons overall (best: FIMO
   p<1e-4, fold 1.35, Fisher p=0.070). At the paper's operating points
   (D-Sites full / top-5% sets) the genome-wide operon hit rate is ~100% —
   saturation, the quantitative refutation of the old "68.1% validation
   success" claim. The FNR-activated-only enrichment survives for FIMO
   (p<1e-4: fold 2.12, p=0.0012; motif-only) but **NOT for D-Sites with the
   new PQT features** (top 0.1%: fold 1.19, p=0.20; the old-table value
   fold 1.62/p=0.0025 did not replicate across shape sources and must not
   be claimed). See CHANGELOG.md and fnr_operon_enrichment.json.
6. **Shape-source adoption** (background documented in `CHANGELOG.md`): the
   untraceable symmetrized dinucleotide table was replaced by the published
   DNAshape predictor (pentamer PQT, Zhou et al. 2013 NAR 41:W56-W62; values
   as distributed in DNAshapeR v1.38.0 and re-implemented in pure Python —
   bit-identical, `pqt_python_vs_R_verification.json`). Performance is equal
   (AmrZ PR-AUC 0.0009) to slightly better (CodY PR-AUC 0.0039) than the old
   table; all numbers in this directory were regenerated with dsites v1.3.0.

## Reproduce
```
cd evaluation/scripts
PY=/tmp/dsites_venv/bin/python
$PY cross_validation.py --tf AmrZ   # (also GlxR, CodY)
$PY run_fimo_fair.py --all --tf FNR_ecoli
$PY make_pr_curves.py --all --boot 1000
$PY ablation.py --all
$PY fnr_transfer.py
$PY summarize_cv.py
$PY fnr_operon_enrichment.py        # Phase 4
```
